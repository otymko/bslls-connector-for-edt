# Проверка запуска соединителя

`BSLConnector.startInThread()` должен подготовить прокси RPC до возврата:
инициализация не должна зависеть от того, успел ли планировщик запустить поток
чтения. Проверка задерживает этот поток защёлкой и сразу отправляет `initialize`.
На прежнем коде получается `NullPointerException`; после исправления запрос
уходит до снятия задержки. Ожидание ответа сервера для этого сценария не нужно.

Запуск из корня репозитория:

```text
python tools/test_connector_startup.py --java-home <JDK-17> --classpath <CLASSPATH>
```

В `CLASSPATH` нужны установленный JAR соединителя, плагины EDT, LSP4J и
LSP4J JSON-RPC версии целевой платформы. Разделитель путей стандартный для ОС:
`;` в Windows и `:` в Linux/macOS. Нужные LSP4J JAR следует поставить раньше
каталогов плагинов, если в установке есть более старая версия.

Сценарий компилирует настоящий `BSLConnector.java` из текущего рабочего дерева.
Минимальная подмена `BSLPlugin` предоставляет только рабочий каталог и
регистрацию ошибок. LSP4J и клиент соединителя используются настоящие.
Проверка не запускает EDT, 1С, внешний языковой сервер или сетевые запросы.
Она дополняет сборку Tycho и живую проверку в EDT.

Дополнительно `ConnectorListenerTest` проверяет завершение потока чтения после
ошибки, отмены и прерывания. Ошибка регистрируется один раз, флаг прерывания
сохраняется. `--source` позволяет повторить проверки на исходнике базового коммита.

`ConnectorDiagnosticTimeoutTest` имитирует ответ диагностики через 11 секунд
и проверяет весь вызов через внешнюю задачу `runFutureTask`. С исходным
ограничением в 10 секунд запрос отменяется до ответа. С ожиданием до 30 секунд
результат получен. `--diagnostic-only` запускает только эту проверку.
